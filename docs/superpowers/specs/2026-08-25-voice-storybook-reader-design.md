# 내 목소리 동화 낭독 앱 — 설계 문서

## 개요
부모(사용자) 본인의 목소리를 클로닝하여, 텍스트 파일로 된 동화책을 캐릭터별로 톤을 바꿔가며
"구현동화"처럼 실감나게 읽어주는 Android 앱. 완전 오프라인으로 동작하며, 개인/가족용으로
먼저 만들고 추후 스토어 배포 가능성을 열어둔다.

## 목표 / 제약
- 목소리 정체성은 항상 사용자 본인 — 톤/감정만 캐릭터에 따라 바뀐다 (여러 목소리가 아님)
- 완전 오프라인 낭독 (인터넷/클라우드 API 불필요, 비용 없음, 프라이버시 보장)
- 모델 학습은 PC(RTX 3060, VRAM 6GB)에서 1회, 폰에서는 추론(낭독)만 수행
- MVP는 음성 낭독까지만 — 배경음악/효과음은 범위 밖 (추후 확장 포인트로 남김)
- 개인 사이드로딩(APK 직접 설치)으로 시작, 스토어 배포를 막는 설계는 피한다

## 전체 아키텍처
두 개의 독립된 파트로 구성된다.

**PC 파트 (학습 도구, 1회성)**
- 녹음 스크립트에 따라 스타일별 음성 녹음
- Piper(VITS 기반) 파인튜닝 + 한국어 발음기(g2pK)로 스타일별 `.onnx` 모델 생성
- 완성된 모델을 안드로이드 앱 프로젝트의 assets로 복사

**Android 앱 파트 (실사용)**
- sherpa-onnx 런타임으로 5개 스타일 모델을 로드해 오프라인 낭독
- 텍스트 파일 로드 → 파싱 → 캐릭터-스타일 매핑 → 순차 합성 및 재생

두 파트는 완전히 분리되어 있어 앱 자체에는 학습 로직이 포함되지 않는다. 목소리 품질을
개선하려면 PC 파트만 재실행하고 새 `.onnx` 파일만 앱에 교체하면 된다.

## 음성 엔진: 왜 Piper(VITS) + g2pK인가
검토한 대안:
- **클라우드 API (ElevenLabs 등)**: 품질은 최상이지만 인터넷 필수, 사용량 과금, 목소리 데이터가
  외부 서버에 저장됨 — "완전 오프라인" 목표와 상충하여 제외.
- **XTTS-v2 파인튜닝**: 한국어 기본 지원, 참고 음성으로 톤 전환이 유연하나 모델이 GB급으로 커서
  폰에서 실시간에 가까운 추론이 현재 기술로 비현실적 (문장당 수십 초 소요 가능) — 제외.
- **Piper(VITS) + sherpa-onnx (채택)**: 안드로이드 온디바이스 실행이 이미 검증된 경량 조합.
  기본 발음기(espeak-ng)의 한국어 품질이 약해 g2pK 기반 한국어 발음기로 보강.

## 스타일 구성
5가지 톤을 모두 "사용자 본인 목소리"로 연기하여 학습한다.
1. 내레이션 — 차분한 서술
2. 주인공 — 호기심·의지가 담긴 대사
3. 악역 — 위협적·낮은 톤
4. 조연 — 친근하고 반응하는 대사
5. 다정한캐릭터 — 부드럽고 다정한 대사

## 녹음 데이터 수집
- 스타일당 20~30분 분량(문장 200~300개), 사전학습 체크포인트에서 파인튜닝하므로 스크래치
  학습보다 훨씬 적은 데이터로 시작 가능. 품질 부족 시 추가 녹음 후 재학습.
- 문장 스크립트는 스타일별 감정에 맞게 작성하고, 한국어 음소(받침·이중모음 등)가 골고루
  섞이도록 구성한다.
- 녹음 형식: WAV, 22050Hz, 모노, 조용한 환경.
- 폴더 구조: `data/{스타일명}/{번호}.wav` + 문장을 매칭하는 transcript 파일.

## 학습 파이프라인 (PC)
- Piper 공식 파인튜닝 스크립트 기반, 스타일별 개별 학습.
- RTX 3060 기준 스타일당 수 시간, 5개 순차 시 하루~하루반 소요 예상.
- 결과물: 스타일당 `.onnx` + `.onnx.json` 한 쌍, 총 5쌍.

## 앱 기능 / 데이터 흐름
- **파일 불러오기**: 안드로이드 파일 선택창(SAF)으로 `.txt` 선택.
- **파싱 규칙**: 한 줄씩 읽어 `이름: 대사` 패턴이면 해당 이름의 대사로, 패턴에 맞지 않는 줄은
  전부 내레이션으로 처리 (안전한 기본값).
- **캐릭터-스타일 매핑**: 파일을 열면 등장하는 고유 캐릭터명을 자동 추출해 목록으로 보여주고,
  사용자가 각각에 5개 스타일 중 하나를 지정. 매핑은 로컬에 저장해 같은 캐릭터명이 다른 동화에도
  나오면 자동으로 재제안.
- **재생**: 문장을 순서대로 온디바이스 합성하며 재생. 다음 문장을 백그라운드에서 미리 합성해
  끊김을 줄인다. 컨트롤은 재생/일시정지/이전·다음 문장 이동(MVP 범위).
- **에러 처리**: 매핑되지 않은 캐릭터는 내레이션 스타일로 자동 대체, 모델 로드 실패 시 안내
  메시지, 특정 문장 합성 실패 시 건너뛰고 계속 진행.

## 기술 스택
- **Android 앱**: Kotlin + Jetpack Compose. 캐릭터-스타일 매핑은 Room(또는 DataStore)에 저장.
  TTS 엔진은 sherpa-onnx의 Android(AAR) 바인딩.
- **PC 학습 도구**: Python (Piper 학습 스크립트 fork).

## 테스트 전략
- 파서(정규식 매칭, 매핑 누락 시 내레이션 폴백)는 유닛테스트로 검증.
- TTS 품질과 재생 흐름은 실제 기기에서 수동 테스트 (자동화 가치가 낮음).

## 범위 밖 (추후 확장 포인트)
- 배경음악/효과음 자동 삽입
- 앱 자동 캐릭터-스타일 추론(AI 기반)
- 스토어 배포에 필요한 심사 대응, 앱 용량 최적화(온디맨드 모델 다운로드 등)
